# Epistemic Integrity Gate (EIG)

> **Latency-contamination and epistemic provenance control for multi-agent reasoning systems.**

What do we actually know, and where did it come from?

In multi-agent systems and algorithmic reasoning pipelines, decision quality degrades when outputs of prior reasoning or subjective agent conclusions re-enter the pipeline as ground-truth observations. The **Epistemic Integrity Gate (EIG)** enforces strict epistemic boundaries, provenance tracking, lane isolation, and staleness detection across cycles.

---

## Key Invariants

1. **Reasoning Outputs Cannot Be Promoted to Facts**: Yesterday's recommendation is not today's market data. An agent or model cannot mint `FACT`, `MARKET_DATA`, or `USER_STATE`.
2. **Weakest-Link Authority**: A derived claim can never outrank the weakest link in its upstream provenance chain.
3. **Strict Isolation Before Consensus**: In multi-agent lanes (e.g., `EDGE`, `HEDGE`, `EP`), agents reason independently behind an `IsolationBarrier` and cannot cross-read or derive from each other's claims until all lanes are sealed.
4. **Staleness & Expiry Enforcement**: High-frequency data (quotes, options chains, yield curves) ages out according to configurable TTLs, generating flags or quarantining expired material.
5. **Content-Addressed Evidence Packets**: The gate produces immutable, SHA-256 digested `EvidencePacket` structures containing accepted, demoted, flagged, and quarantined claims.

---

## Epistemic Hierarchy & Authority

EIG categorizes all claims into an ordered epistemic hierarchy:

| Epistemic Type | Authority | Category | Description |
| :--- | :--- | :--- | :--- |
| `FACT` | 100 | Observed | Verified ground truth |
| `MARKET_DATA` | 90 | Observed | External market feeds (quotes, ticks, order books) |
| `USER_STATE` | 80 | Observed | System-of-record state (portfolio holdings, account balances) |
| `PRIOR` | 50 | Derived | Historical priors and baseline distributions |
| `ASSUMPTION` | 40 | Derived | Explicit model assumptions |
| `HYPOTHESIS` | 30 | Derived | Hypotheses generated by models or agents |
| `AGENT_OPINION` | 20 | Derived | Subjective agent recommendations or convictions |

## Quickstart

```python
from datetime import timedelta
from eig import EpistemicIntegrityGate, EpistemicType, SourceKind
from eig.types import utcnow

# 1. Initialize gate for a reasoning cycle with isolated agent lanes
gate = EpistemicIntegrityGate(cycle=1, agents=("EDGE", "HEDGE", "EP"))

# 2. Ingest external observations
quote = gate.observe(
    subject="NBIS",
    statement="last 38.10",
    source="polygon",
    tags=("quote",),
    value=38.10,
)
gate.observe(
    subject="PORTFOLIO",
    statement="NBIS 4.2% weight, unhedged",
    source="broker",
    etype=EpistemicType.USER_STATE,
    kind=SourceKind.SYSTEM_OF_RECORD,
)

# 3. Agents submit hypotheses independently in their lanes
gate.agent_claim(
    agent="EDGE",
    subject="NBIS",
    statement="NBIS rebounds into Q3",
    upstream=(quote.id,),
    confidence=0.55,
)
gate.agent_claim(
    agent="HEDGE",
    subject="NBIS",
    statement="tail risk underpriced at current weight",
    confidence=0.70,
)
gate.agent_claim(
    agent="EP",
    subject="NBIS",
    statement="no execution edge above 38.50",
    etype=EpistemicType.AGENT_OPINION,
)

# 4. Seal all agent lanes
for agent in ("EDGE", "HEDGE", "EP"):
    gate.seal(agent)

# 5. Adjudicate and build the evidence packet
packet = gate.build_packet()
print(packet.summary())

# Ensure no quarantined items exist before executing decisions
clean_packet = packet.assert_clean()
```

## Modules

- [src/eig/gate.py](src/eig/gate.py): Single entry point `EpistemicIntegrityGate` orchestrating ingestion, isolation, adjudication, and packet emission.
- [src/eig/types.py](src/eig/types.py): Core data models (`Claim`, `Provenance`, `EpistemicType`, `SourceKind`, `AUTHORITY`).
- [src/eig/isolation.py](src/eig/isolation.py): `IsolationBarrier` managing per-agent lane isolation and prevent cross-reading before sealing.
- [src/eig/contamination.py](src/eig/contamination.py): `ContaminationDetector` identifying opinion laundering, authority inflation, and latency contamination across cycles.
- [src/eig/staleness.py](src/eig/staleness.py): `StalenessDetector` assessing TTL age-outs and expirations.
- [src/eig/packet.py](src/eig/packet.py): `EvidencePacket` and `Quarantined` data structures with SHA-256 digest computation.
- [src/eig/errors.py](src/eig/errors.py): Structured findings and exception hierarchy (`Finding`, `Severity`, `IsolationViolation`, `ContaminatedPacket`).

## Trade Coordinator Core

`eig.coordinator.Coordinator` composes the EIG packet boundary with a typed,
stage-aware candidate registry. It provides:

- immutable candidate lifecycle events and separate `BRANDED_TRADE_SET` and
    `ALGO_SINGLE` identities;
- gate definitions/evaluations where `WARN` does not become `FAIL`, while
    required `UNKNOWN` and `STALE` results block only their stage;
- structured `LCAE` records for collective-action failures and independent
    sleeve rescue with fresh child identity and no inherited conviction;
- decimal expected-value, sensitivity, and risk-unit sizing helpers; and
- proposal-only execution handoff. Account availability and the kill switch
    can block execution, but cannot delete or erase a research candidate.

The Coordinator has no broker capability. `generate_execution_proposal` creates
an immutable `PROPOSED` payload and `approve_exact` requires its exact hash;
approval remains blocked when the account is unavailable or the kill switch is
locked. The current implementation is an in-process compatibility layer for
the dependency-free library. Its event and typed-domain boundaries are designed
to be backed by a persistent repository without changing EIG's public APIs.

Install the optional HTTP adapter with `pip install -e ".[web]"`, then launch
it with `uvicorn eig.app:create_app --factory`. The API includes health,
candidate, meeting-surface, audit, disposition, proposal, and exact-hash
approval operations. It deliberately has no broker endpoint.

Additional Coordinator modules are available for `EvidenceRecord` and
content-addressed `EvidenceStore`, `DecisionCoverageMatrix`, typed
`AgentPacket`, `OpportunityClock` and information-value routing, gate
analytics, and deterministic safety replays. `RootExecutionEngine` remains
the only domain object that accepts a broker adapter.
